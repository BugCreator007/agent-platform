## 三、产品视角问题与答复（会前预答）

| # | 产品可能问 | 开发答复 |
|---|---|---|
| P1 | 为什么上线后用户看不到旧对话？ | 旧会话没有 `user_id`，无法可靠判断归属；自动归属会造成越权。建议上线公告 + 管理员手工归属工单，后续迭代做账号认领。 |
| P2 | 删除会话后管理员还能看到，算不算「没删干净」？ | 用户侧不可见、不可恢复；保留的是审计与统计事实。若产品要求彻底删除，可改为物理删除，但会丢失该会话的反馈与洞察数据。 |
| P3 | 有效会话为什么和「会话数」差这么多？ | 有效会话要求出现追问、点赞或复制/下载；只打开或只问一句没有后续动作不算。指标卡会同时展示会话数与有效会话率，避免误读。 |
| P4 | 反馈原因能不能自定义？ | 本轮六类内置，编码入库、文案集中管理；后续可加管理端配置，不影响数据结构。 |
| P5 | 洞察页为什么没有「版本对比」和「成本」？ | 这两项依赖真实评测（P1-6）与真实成本（P1-5），当前是演示数据，放上去会损害可信度；本轮只回答「用没用、哪里没用」。 |
| P6 | 高频问题会不会把测试账号算进去？ | 本轮会。建议测试使用独立账号并在验收后清理数据；后续加账号标签过滤。 |
| P7 | VIEWER 演示账号还能看运行追踪吗？ | 只能看自己的会话；管理端演示改用 admin/developer。用户端演示不受影响。 |
| P8 | 复制和下载算采纳，会不会被滥用？ | 它们是弱采纳信号，所以有效会话还接受追问与点赞；指标页会同时展示三类信号的数量，避免单一信号误导。 |

## 四、测试视角问题与答复（会前预答）

### 4.1 测试范围

**测**：会话归属与越权、会话列表/改名/删除、反馈提交/修改/撤回、事件落库与失败降级、洞察指标与脱敏、角色权限、移动端基础交互、V11 迁移在 H2 与 MySQL 的兼容。

**不测**：模型回答质量、真实评测执行、成本计算、开放 API、模板中心、第三方分析平台。

### 4.2 重点用例

| # | 场景 | 预期 | 类型 |
|---|---|---|---|
| T1 | A 登录读 B 的会话消息/续聊/改名/删除 | 全部 404，且不泄露会话是否存在 | 安全 |
| T2 | 未登录访问用户端任意会话接口 | 401 | 安全 |
| T3 | VIEWER 调管理端会话列表 | 只返回本人会话 | 权限 |
| T4 | VIEWER 调洞察/反馈列表 | 403 | 权限 |
| T5 | A 对 B 的消息提交反馈 | 404 | 安全 |
| T6 | 同一消息连续点赞→点踩→撤回 | 始终一条记录，状态正确，按钮同步 | 功能 |
| T7 | 点踩不选原因 / 纠错文本 501 字 | 400，提示明确 | 边界 |
| T8 | 会话标题 0 字 / 61 字 / 纯空格 | 400 | 边界 |
| T9 | 删除会话后刷新、换设备、直接访问 ID | 列表消失、404 | 功能 |
| T10 | 对话过程中关闭浏览器 / SSE 中断 | 用户消息保留，会话状态可解释，不产生脏事件 | 异常 |
| T11 | 模型失败/超时 | 出现 `answer_failed`，用户看到错误提示，会话可重试 | 异常 |
| T12 | 事件表写入失败（改表名模拟） | 对话成功，日志 WARN，失败指标 +1 | 降级 |
| T13 | 客户端事件名不在白名单 / 属性 1.1KB | 400 | 安全 |
| T14 | 同一用户 1 分钟上报 130 次事件 | 超出部分 429，前 120 次成功 | 限流 |
| T15 | 洞察窗口 0 / 91 天 | 400 | 边界 |
| T16 | 无数据窗口打开洞察页 | 空状态，无 NaN/500 | 体验 |
| T17 | 问题/注释含手机号、身份证、银行卡 | 接口返回与页面均掩码 | 隐私 |
| T18 | 两个浏览器同时给同一消息反馈 | 唯一约束生效，最后写入为准 | 并发 |
| T19 | 会话列表 25 条、page=2、size=20 | 返回 5 条，total 正确 | 分页 |
| T20 | V11 在已有 V1–V10 数据的库上升级 | 启动成功，旧会话可查，`updated_at` 回填 | 迁移 |

### 4.3 测试数据

- 需要两个普通账号（如 viewer + 新建 `tester`）和一个开发者账号，验证隔离与权限。
- 至少构造：3 个智能体、每个 5 个会话、20 条消息、10 条反馈（含 4 条 👎、2 条已处理）、30 条事件，覆盖近 7 天。
- 敏感样本：手机号、18 位身份证、16 位银行卡各 1 条，验证掩码。
- 演示数据由 `InsightDataSeeder` 生成，测试环境可重复执行；清理脚本由测试维护。

**准出**：T1–T20 全部通过；`mvn test`、两个 `npm run build` 通过；无 P0/P1 缺陷；上线清单与回滚步骤确认。
