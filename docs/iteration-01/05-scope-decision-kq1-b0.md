## 1. 决策

本轮迭代（迭代 01）范围收口为两项：

1. **KQ-1 回答反馈与无答案识别**：消息级 👍/👎、原因标签、纠错文本；HYBRID 低置信提示；STRICT 严格拒答；拒答与反馈落库；管理端反馈列表与统计。
2. **B0 产品埋点基线**：服务端 6 类事件 + 客户端 3 类事件落库，支撑有效会话、漏斗与后续缺口分析。

同时纳入一项安全修复：**会话读接口属主校验**（否则任意登录用户可读任意会话，反馈归属也失去意义）。

顺延项：

- A1 完整会话管理（列表、重命名、软删除、跨设备续聊）→ 下一迭代；
- B2 会话洞察页（指标卡、漏斗、未解决问题、高频问题）→ 下一迭代；
- KQ-2 知识缺口看板、KQ-3 引用可信化、KQ-5 文档治理 → 下一轮主线；
- KQ-4 真实评测与回归 → 单独立项，不在本轮。

## 2. 口径冻结（冲突时以此为准）

1. **迁移编号**：V11 保持 2026-11-17 已执行的版本不变（本地 checksum `407078699`）；V12 = `product_events`；V13 = 复审新增的 `retrieval_json`、`handle_status`、`reasons_csv`、`agent_name` 与状态索引。后续迁移按 V14+ 顺延，禁止原地修改已执行迁移。
2. **归属字段**：唯一使用 `chat_sessions.created_by`（登录名），本轮**不新增** `user_id`；P1-8 做完整会话隔离时再迁移。新会话写入当前登录用户，管理端调试会话写入操作人。
3. **越权修复**：`GET /api/v1/sessions`、`GET /api/v1/sessions/{id}`、`GET /api/v1/sessions/{id}/messages` 必须校验 `created_by`；`created_by IS NULL` 的历史会话仅 `PLATFORM_ADMIN` / `DEVELOPER` 可见；管理端会话接口补角色限制；反馈只允许会话所有者提交（历史无主会话不允许反馈）。
4. **反馈口径**：原因统一为 PRD 六类——`NOT_RELEVANT`（答非所问）、`INCOMPLETE`（不完整）、`OUTDATED`（信息过时）、`WRONG_SOURCE`（依据不对）、`NO_SOURCE`（没有依据）、`OTHER`（其他）；备注 ≤200 字；编码入库、文案集中管理。
5. **拒答策略**：HYBRID（默认）在绑定知识库但 0 命中时正常回答并标 `low_confidence=true`，前端展示「未检索到相关资料」提示；STRICT 在 0 命中时不调用模型、直接返回拒答卡片。**STRICT 仅允许绑定向量或混合检索数据集**，纯关键词数据集禁用并给出提示（关键词路无阈值，拒答会失效）。
6. **检索诊断**：每条助手消息持久化 `hitCount/topScore/mode/noHit`（JSON），供 KQ-2 与复盘使用；`product_events` 不记录问题原文与 PII。
7. **反馈处理状态**：本轮反馈表至少保留 `handle_status`（OPEN/HANDLED/IGNORED）扩展位，B2 顺延时不必再改表；若实现成本高，可放 V12 一并加。

## 4. 验收清单

1. 员工对一条回答点赞/点踩后刷新，状态仍在；同一用户对同一消息只有一条记录，可修改、可撤销。
2. 点踩必须选 1–2 个原因；备注 >200 字被前后端拒绝；对用户消息或他人消息反馈返回 404/403。
3. STRICT 智能体在 0 命中时返回拒答卡片，模型请求次数为 0；拒答消息落库且管理端可见。
4. HYBRID 0 命中时正常回答，带低置信提示，`low_confidence=1`。
5. A 看不到 B 的会话；A 按 B 的会话 ID 读消息/详情返回 404；历史无主会话用户端不可见。
6. 管理端可按智能体、时间、评分、原因筛选反馈；列表与统计一致；VIEWER 访问 403。
7. 删除会话后消息与反馈级联清理，无残留。
8. 普通与 MCP 两条 SSE 分支的 `done` 均返回 `assistantMessageId/answerType/lowConfidence`。
9. 完成一次对话后，事件表依次出现 `session_started`、`message_sent`、`answer_completed`；失败出现 `answer_failed`；复制/下载/反馈事件归属正确。
10. 事件写入失败时对话正常完成，日志 WARN 且失败计数 +1；同一 `event_id` 重试只落一条。
11. V11、V12 在 H2 与 MySQL（已有 V1–V10 数据）上升级成功，旧数据字段回填/默认值正确。
12. `mvn test`、`admin-web` 与 `user-web` 构建通过；关键接口完成 401/403/200 验证。

## 7. 风险

1. **越权修复会触碰现有会话接口**：user-web 与管理端运行追踪都在用，需回归；历史无主会话用户端不可见，需公告。
2. **STRICT 限制数据集类型**：纯关键词知识库不能选严格模式，演示脚本需调整。
3. **测试基础薄**：本轮新增链路必须自带单测/集成/E2E，合入前 `mvn test` 与双前端构建必须通过。
4. **反馈率天然偏低**：不设硬性 KPI，先建基线；反馈覆盖率低于 10% 时不要解读采纳率。
5. **埋点写放大**：非 GET 已有审计同步写，事件必须 after-commit、异步批量、幂等，并设保留期。
